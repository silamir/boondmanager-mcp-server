# CLAUDE.md - BoondManager MCP Server

## Project Overview

MCP (Model Context Protocol) server for the BoondManager API. Exposes
**240 tools, 24 prompts, 48 resources, 6 resource templates** across 43
domains, allowing Claude to interact with BoondManager ERP/CRM data. The exact catalogue is
auto-generated in `TOOLS.md` (regenerated by `npm run docs:tools`); the figures
above are asserted against a real client by `src/catalogue-counts.test.ts`.

TypeScript strict, Node >= 22, stdio (default) and Streamable HTTP transports, JSON:API
upstream, Apache-2.0. Annotated source map: `docs/architecture.md`.

## Commands

```bash
npm run build                 # tsc
npm test                      # vitest run
npx vitest run src/tools/candidates.test.ts   # one file
npm run test:coverage         # + per-folder / per-file coverage floors (CI gate)
npm run lint                  # ESLint (typed rules)
npm run typecheck             # tsc --noEmit
npm run docs:tools            # regenerate TOOLS.md (…:check in CI)
npm run plugin:manifest       # regenerate plugins/boondmanager-mcp/ from manifest.json (…:check in CI)
node scripts/measure-tools-list.mjs           # real tools/list size (CI ceiling MAX_TOOLS_LIST_KIB)
```

Done means: `npm test && npm run lint && npm run typecheck && npm run build` green, plus
`npm run docs:tools:check` when a tool, prompt or resource changed. Run `npx vitest run`
on its own line — piping it into `grep` hides a red suite. Show the command and its output
as evidence rather than "tests pass".

Local live probe (read-only, sandbox credentials from `.env`):
`set -a; source .env; set +a; node scripts/smoke-live.mjs`. The tenant usually reachable
is **production**: never exercise a POST / PUT / DELETE against it.

## Gotchas that apply everywhere

- **Wrong filter names are silently ignored by BoondManager** and return the unfiltered
  baseline. Search-schema keys are the exact RAML query-parameter names
  (`https://doc.boondmanager.com/api-externe/raml-build/`), and no list endpoint accepts
  a `companyId` / `projectId` / `resourceId`: those go through `toKeywordReferences()`
  into `keywords` prefixes (`CSOC<id>`, `PRJ<id>`, `COMP<id>`…). Details: `search-filters.md`.
- **Every id input is `EntityIdSchema`** (`/^\d+$/`); document ids are the one exception
  (`DocumentIdSchema`, `123_resume`). A bare `z.string()` let `"5/information"` reach an
  API path; `id-schemas.test.ts` walks every advertised schema.
- **`state` on write schemas**: absent where BoondManager's validation workflow owns it
  (expenses, timesheets, absences), `stateField` where it persists. Never a bare `z.number()`.
- **Unverified write paths say so.** Many POST / PUT bodies were derived from the RAML and
  `models.<entity>` without a test tenant; their description and rule file mark them
  "not exercised". Don't upgrade that claim without a live write.
- **The catalogue counts are tested**: adding a tool / prompt / resource means editing the
  sentence above *and* the one in `README.md`, then `npm run docs:tools`. Do not quote a
  test count anywhere (it rots; a test forbids it).
- **Generated files** — `TOOLS.md`, `plugins/boondmanager-mcp/**` — are never hand-edited
  (a hook blocks it). Edit the source (`manifest.json`, registrations) and regenerate.
- **`TOOL_REGISTRARS` order is API** (deterministic `tools/list`, prompt-cache hits): append.
- **stdout is the JSON-RPC stream on stdio**: every log goes to stderr through
  `src/services/logger.ts`; never `console.log`.
- **Read env through `src/config/env.ts`**, never `process.env` directly — blank,
  whitespace and unsubstituted `${…}` values must all mean "unset".
- **Imports of the HTTP client** go through the barrel `src/services/boond-client.ts`
  (tools, transports, resources and test mocks), never `services/http/*` directly.

## Conventions

- French for tool / prompt / resource titles and descriptions; English for code, comments,
  commit messages and `CHANGELOG.md` headings.
- Tool names: `boond_{domain}_{operation}`; tab tools `boond_{entity}_{tab}` (hyphens → `_`).
- Every tool declares accurate annotations — they drive the access-control operation filter.
- Indexed access is narrowed with a guard or `?? default`, never `!`; optional properties
  are omitted, not set to `undefined` (`exactOptionalPropertyTypes`).
- `noUncheckedIndexedAccess`, typed ESLint: fix the site, don't widen the test-file override.

## Git workflow

- `main` is protected by rulesets: branch `type/short-name`
  (`feat|fix|chore|docs|ci|build|…`), conventional-commit PR title, five required checks
  (`Titre de PR`, `Lint PR commits`, `Scan for secrets`, `Pre-commit hooks`, `Qlty check`)
  plus CodeQL; unresolved review threads block the merge even when green.
- Stage by explicit path (a hook blocks `git add -A` / `git add .`: untracked CRM extracts
  were once pushed). Check `git status --short` before committing.
- One branch per ticket, `Closes #N`, a `CHANGELOG.md` `[Unreleased]` entry; parallel
  tickets in a `git worktree` (`.worktreeinclude` copies `.env`).
- Personal notes go in `CLAUDE.local.md` (gitignored), not here.
